# Osmo Nano BLE Ctrl

Windows PCから、電源が入っているDJI Osmo Nano 1台の録画開始・停止をBLEで操作する小さなツールです。Wi-Fi転送、電源OFF状態からのwake、他のDJIカメラは対象にしていません。

## 起動

Windows 11、Bluetooth LEアダプター、Python 3.13、`uv`を想定しています。`uv`が依存関係とリポジトリ内の専用`.venv`を管理するため、他のPythonプロジェクトには影響しません。次のコマンドは`uv.lock`に従って環境を自動同期してから起動します。

```powershell
uv run osmo-ble-ctrl
```

## 操作手順

1. Osmo Nanoの電源を入れます。
   初回承認ではNanoをVision Dockへ取り付け、画面を操作できる状態にしてください。DJI MimoはNanoとの接続を切っておきます。
2. `uv run osmo-ble-ctrl`を実行します。
3. 「Nanoを検索」→対象を選択→「接続」の順に操作します。
4. 初回だけ、Nano画面に表示される`OSMOCTRL`を承認します。これはアプリ内ペアリングで、WindowsのBluetoothペアリング操作は不要です。
5. 接続と承認が完了した後、「録画開始」または「録画停止」を押します。

録画ボタンを押した直後は「コマンド送信済み（カメラ確認待ち）」と表示します。DUMLのACKはコマンド受理の意味であり、録画の成功そのものではありません。「カメラ確認済み」はNanoから届くstate pushで確認できた場合だけ表示します。15秒以内に確認できなければ未確認として報告します。

## 注意事項

- Nanoは起動した状態で検索してください。本ツールはスリープ中のNanoを起こしません。
- Nano名または広告内のNanoモデルID (`0x19`) で識別できる機器だけを一覧に出します。
- 初回承認に使う32桁の識別子は`%LOCALAPPDATA%\OsmoBLECtrl\settings.json`へ保存し、次回も同じ値を使います。
- 接続中はセッション維持のため1秒ごとにkeepaliveを送信します。
- BLEアダプターとのネゴシエーション後のwrite-without-response上限がペアリングフレームより小さい場合、安全に分割できないため送信せずエラーにします。
- 実機やファームウェアの組み合わせによっては動作しない可能性があります。問題調査には画面下部の通信ログを利用してください。ログにはWi-Fiパスワード等は含まれません。
- このリポジトリ作成時点では、自動テストとWindows上のGUI起動・BLEスキャンまでを確認し、実機Nanoへの接続・承認・録画操作は実施していません。

## 開発・テスト

テスト用依存関係を事前に同期する場合は、次を実行します。この操作は任意です。

```powershell
uv sync --extra test
```

テストは次のコマンドだけでも、必要な依存関係を自動同期して実行できます。

```powershell
uv run --extra test pytest
```

通信プロトコルの根拠とライセンスは[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)に記載しています。実機を使わないテストでは、DUML CRC、通知の分割・連結・破損、ペアリング分岐、録画コマンド、state pushの保守的な判定を検証します。
